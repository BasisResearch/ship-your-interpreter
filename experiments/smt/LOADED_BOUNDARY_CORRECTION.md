## Final assumption change

Keep the abstract definitions `Layout`, `Loaded`, and `InterpSim`. Correct `LayoutInstance.interpRunLayout.atInterpRun`, currently `InterpRunReady`, to describe the actual script-mode call from main. Consequently the concrete theorem still prints `Loaded interpRunLayout p c`, but its premise changes. This must be disclosed as a final-assumption change. Do not assert an implication from the old boundary to the corrected boundary.

The proposed added constraints below are finite register equalities, memory reads, code-byte equalities, and memory-region disjointness. Existing program/store representation and output assumptions remain. The correction does not move the boundary back to CRT startup or assume parser correctness.

## Fixed instruction and read-only data image facts

The correction includes interpreter child/helper instructions and dispatch data. Use these two exact fixed-image byte predicates:

- `FixedTextLoaded mem`: every byte in ELF `.text`, `[0x80000000,0x80018be0)` (101344 bytes), equals the corresponding byte of the fixed ELF identified above.
- `FixedRodataLoaded mem`: every byte in ELF `.rodata`, `[0x80018be0,0x8001acf0)` (8464 bytes), equals the corresponding fixed ELF byte.

These are concrete byte equalities, not execution assumptions. They cover `exec_stmt`, `eval_expr`, value/environment/allocator/native/libc helpers, the clean tail, and read-only dispatch tables. Existing `run_code` and `setjmp_code` become projections. Keep the mutable-data portions of `ImageStaticsLoaded` and the initialized runtime-data predicates separately; neither `.text` nor `.rodata` includes mutable `.data` or BSS. Derive existing fragment predicates through generated byte projection lemmas, then preserve the image through actual effects.

Why required: `ImageStaticsLoaded` is exactly eight snprintf data-range predicates (`Code/ImageStatics.lean:103`). `ImageDischarge.lean` explicitly excludes code. `ExecSeqEntryI.code` supplies only its physical copy image (`interpRun` supplies only `Interp_runLoaded`); child `ExecEntry.code` requires `Exec_stmtLoaded`, while `ExecGround.eval_call` requires expression/value helper code and dispatch data. No import or code generator establishes those facts for arbitrary `c.σ.mem`. The old boundary permits absent/modified bytes at child function entries. Full child code cannot be derived from it.

## Preservation and remaining schema work

Require concrete region disjointness between the chosen arena and the protected code/runtime data/main saved pair. Prefer the exact finite disjointness predicate to imposing a new allocation policy. A linker-derived arena bound would be a stronger alternative requiring separate justification; this proposal does not authorize it automatically. Existing assumptions do not currently pin arena bounds tightly enough to infer these disjointness facts.

The final list of byte-presence predicates and the smallest close write footprint are not yet machine-checked. The intended writes are stack scratch, FILE flags/cursor/counts, and errno. Before implementation, audit the reached instruction subsets against these fields. Add only missing concrete read/presence/geometry facts from those decoded instructions. Any further semantic assumption requires renewed approval.

In particular, stdout's new close/auxiliary-buffer fields lie inside the current broad `ConsoleFoot`. An outside-ConsoleFoot frame alone cannot preserve them. Native output proofs must preserve these fields explicitly or expose their actual narrower write region. Do not assume preservation as another boundary oracle.
