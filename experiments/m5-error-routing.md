## The mechanical pattern (fully mechanical — 100%)

Every premise is discharged by the identical term, byte-for-byte modulo the
premise's argument-intro count and its site PC/bytes:

```
fun c _ … _ =>                                  -- intro c + N underscores
  errRow S.g S.inp S.ra0 … S.spv S.m0 S.SC S.out S.HT
    (SitePre := JalErrPre S.g S.inp S.m0 <pc> <b0> <b1> <b2> <b3>)
    (errSite_<pc> S.g S.inp S.m0) c (hsite c)
```

`errRow` (`ErrorSiteRows.lean`) is polymorphic in `SitePre`; the per-site
`Triple T` slot is supplied by the generated `errSite_<pc>` (proved
unconditionally by `#derive_error_site`). So the discharge is one application,
NOT a machine proof. The only per-premise variation is (a) the intro-arity
(computed from the premise signature) and (b) the site PC/bytes. Both are
table-driven; the generator emits all 42 rows + the capstone + the wiring
example from the TSV. This is a genuine table+one-application-shape, exactly the
form the mission asked for — no 42 hand instantiations.

## The per-premise residual — the 42 reachability links (M4 caller-linkage)

The ONLY per-premise residual is
`hsite_<name> : ∀ c, JalErrPre g inp m0 <pc> <bytes> c` — that config `c`, when
the machine runs the compiled error node to its `jal runtime_error`, is parked at
that jal with the ErrorIn pointer in `x10`, memory `m0`, and the `g` frame. This
is the M4-side caller-linkage: the forward-sim of each error node's dispatch
prefix up to its jal. It is NOT dischargeable in this routing task — it is genuine
M4 semantic content (the term-sim assembly provides the analogous per-case entry
facts). It stays a named hypothesis of `errFamilyClosed`, exactly as
`ErrorSiteApplied.row_hNegType_applied` leaves `hsite` a hypothesis.

## Note on the premise→PC assignment (honest)

`errRow` is polymorphic in `SitePre`, so ANY proved `errSite_<pc>` closes ANY
premise given a matching `hsite`. The premise→PC assignment in the TSV distributes
the 19 sites across the 42 premises **structurally** (grouped by dispatch region:
EvalErr → 0x8000345c…0x80003da0 band; EvalArgsErr/ForLoopErr → 0x80003de8…
0x80003fdc band; CallErr/ExecSeqErr → 0x80002e90/0x80002ebc). The ONE
semantically-pinned mapping is `hNegType → 0x800034e4` (proved live in
`ErrorSiteApplied`). The precise premise→PC map for the other 41 is the M4
caller-linkage that `hsite` abstracts; fixing it only changes which
`JalErrPre <pc>` shape the reachability residual takes, not the routing structure.
When M4 supplies each node's actual reached jal, regenerate the TSV's `site_pc`
column and re-run the generator (the bytes are derived from the site word, so they
always match the proved `errSite`).

## Mechanical-duplication observations

* The 42 rows differ ONLY in intro-arity + site PC/bytes; everything else is
  byte-identical. Fully generator-driven — no hand rows.
* The `errRow` call is the same 5 lines in every row. If a future combinator
  wanted to erase even the arity variation, `errRow` could be η-expanded behind a
  `∀`-erasing wrapper, but the current table form is already ~100% mechanical and
  costs nothing at elab time.
* Byte order: `JalErrPre`/`errSite` take little-endian `(b0 b1 b2 b3)` of the jal
  word; the generator derives them from `SITE_WORD` (ground-truth from the proved
  batches) so they can never drift from the `errSite_<pc>` Triple.
